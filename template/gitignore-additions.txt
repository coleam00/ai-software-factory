# Appended to your .gitignore by `factory init`.

# THE FACTORY'S OWN BYTECODE. Every factory script is Python, and running one inside a
# worktree writes `factory/__pycache__/*.pyc` -- inside `factory/`, which is on the
# PROTECTED list. A builder's `git add -A` then sweeps them in and the guard blocks the
# change for touching a protected path, which is exactly right and completely useless:
# the lap dies with five .pyc files named as the violation and the actual work sitting
# beside them, correct and unmergeable.
__pycache__/
*.pyc
*.pyo

# THE FACTORY'S OWN PYTHON ENVIRONMENT. Every script node declares `runtime: uv`, and
# uv materialises a virtualenv and a lockfile in the checkout the first time one runs.
# Same shape as the bytecode above, one level worse: the implement lap's `git add`
# swept `uv.lock` into a commit that was supposed to be a one-line ORDER BY change, and
# then the VALIDATOR could never run -- `prepare` checks out the PR branch, git refuses
# to overwrite an untracked `uv.lock` with the branch's committed one, and the pull
# request becomes permanently unvalidatable. It parks at needs-human, correctly, forever.
#
# Ignored files ARE overwritten by a checkout, which is why ignoring it is the fix and
# not merely tidiness.
#
# IF YOUR PROJECT GENUINELY MANAGES ITS OWN DEPENDENCIES WITH UV, delete these two lines
# and commit your lockfile -- it is yours, not the factory's, and pinning it is correct.
# They are here because the common case is a repo that never chose uv and got one
# because the runner did.
.venv/
uv.lock

# Secrets. THE PRE-FLIGHT REFUSES TO START while any of these is unignored, and that
# refusal is the point: an empty `git check-ignore` result means the next run that
# commits publishes your key. On a public repo that is publication, not a mistake you
# can take back -- rotating afterwards is the cleanup, not the fix.
#
# Being unable to EDIT a protected file does not stop a broad `git add` from

# is separate from the protected list and checked before every committing workflow.
